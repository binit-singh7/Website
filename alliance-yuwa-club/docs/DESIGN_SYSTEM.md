# Alliance Yuwa Club
## Design System & Visual Direction — V1
> **Design principle: Do not make Alliance Yuwa Club look like a website generated by AI. Make it look like Alliance Yuwa Club.**
---

# 1. Purpose

This document defines the visual identity, user experience principles,
layout rules, typography, color system, motion language, responsive
behavior, and UI implementation rules for the Alliance Yuwa Club website.

The website must feel like a real youth-led community organization with
a strong identity.

It must NOT look like a generic AI-generated NGO, SaaS, startup, or
portfolio website.

This document is the source of truth for frontend visual design.

---

# 2. Design Goal

The primary design goal is:

> Create a visually distinctive, modern, energetic, human, and
> trustworthy digital identity for Alliance Yuwa Club.

The experience should communicate:

- Youth
- Leadership
- Unity
- Community
- Action
- Service
- Energy
- Trust
- Local identity
- Modern thinking

The design should feel appropriate for a real organization based in
Biratnagar, Nepal.

4. Design Inspiration

The visual direction takes inspiration from premium digital studios
such as Pixel One.

The inspiration is based on design philosophy rather than copying any
specific website, layout, artwork, animation, or branding.

Key principles inspired by this direction:

Strong visual hierarchy.
Brand-first design.
Editorial composition.
Typography as a major visual element.
Carefully controlled whitespace.
Intentional asymmetry.
Strong photography.
Motion used as part of the experience.
Clean but expressive interfaces.
Distinctive page composition rather than template layouts.

The Alliance Yuwa Club website must maintain its own visual identity and
must never reproduce another company's design.

7.2 Use Whitespace Intentionally

Whitespace should create hierarchy and breathing room.

Do not attempt to fill every part of the screen.

A section may intentionally contain:

One image.
One statistic.
One call to action.
7.3 Avoid Perfectly Repetitive Grids

Not every section should use:

Use a mixture of:

Two-column compositions.
Asymmetric layouts.
Overlapping elements.
Large image blocks.
Editorial layouts.
Horizontal lists.
Structured grids where appropriate.

The composition should change naturally between sections.

The homepage should have visual rhythm.

For example:

Image-heavy
       ↓

       ↓
Editorial content
       ↓

8. Anti-Generic AI Design Rules

The following patterns must NOT be used as the default visual language:

❌ Purple-to-blue gradients everywhere
❌ Generic SaaS hero section
❌ Floating gradient blobs
❌ Excessive glassmorphism
❌ Excessive rounded cards
❌ Three identical feature cards repeated
❌ Generic stock illustrations
❌ Random decorative icons
❌ Excessive drop shadows
❌ Every section inside a rounded rectangle
❌ Excessive pill-shaped buttons
❌ Generic "Empowering communities..." copy
❌ Unnecessary 3D objects
❌ Excessive floating animations
❌ Animation on every element
❌ Copying common AI-generated landing page templates

The AI must consciously avoid falling back to these patterns.

# 9. Color System

The Alliance Yuwa Club color system is derived from the colors visibly
present in the official club logo and branding.

The color palette must reinforce the identity of the organization as
youthful, community-oriented, energetic, trustworthy, and connected to
service and the environment.

The logo is the primary visual reference.

Important:

- The HEX values below are web-design values sampled/approximated from
  the supplied logo artwork.
- They should be treated as the current website design palette, not as
  legally defined official brand specifications.
- If an original high-resolution SVG/PNG brand asset or official brand
  guide provides different exact values, the official source takes
  priority.
- AI coding agents must not replace this palette with unrelated trendy
  colors.

9.7 Color Hierarchy

The website should visually prioritize colors in this order:

1. Neutrals
2. Primary Green
3. Primary Blue

Brand colors should create visual identity rather than cover the entire

9.8 Recommended Color Balance

The following is a design guideline, not a strict mathematical rule:

60–70%  Neutral background / surfaces
10–15%  Primary green
5–10%   Primary blue
2–5%    Orange accent
1–3%    Yellow accent
Remaining area: typography, borders, imagery, and contextual colors

Photography may visually occupy much more space without counting toward
these UI color percentages.

The purpose of this ratio is to prevent the website from becoming
visually overloaded with brand colors.

9.22 Prohibited Color Practices

AI coding agents and developers must NOT:

Replace the palette with purple/blue SaaS colors.
Randomly introduce neon colors.
Use gradients on every section.
Use five or more accent colors in one section.
Use bright yellow for long-form text.
Use light green/light blue for body text without checking contrast.
Use arbitrary HEX values when an existing design token is appropriate.
Create page-specific palettes without design approval.
Use color purely for decoration when it harms readability.
9.23 AI Color Decision Rule

Before introducing a new color, the developer or AI agent must determine:

Does an existing design token already serve this purpose?
Why is a new color necessary?
Is the color derived from the existing brand identity?
Does it maintain sufficient contrast?
Will it remain visually consistent across the website?

If an existing token can perform the same job, use the existing token.

Do not create a new color unnecessarily.

27. Motion Design Philosophy

Motion is part of the visual identity, but it must remain purposeful.

Core principle:

Motion should improve hierarchy, feedback, continuity, or emotion.

It must not exist only because animation is technically possible.

28. Motion Categories
28.1 Entrance Animation

Elements may subtly:

Fade in.
Move vertically.
Reveal through clipping.
Scale slightly.

Use short, smooth transitions.

28.2 Scroll Reveal

Sections may reveal as they enter the viewport.

Examples:

Section title
Image
Activity item
Statistics

Use staggered animation only when it improves hierarchy.

Do not animate dozens of elements independently.

28.3 Hover Interaction

Possible hover effects:

Image scale: subtle
Text movement: subtle
Arrow movement
Underline/reveal
Border transition

Hover effects should not be distracting.

28.4 Image Motion

Images may use:

Gentle scale.
Parallax.
Clip-path reveal.
Position shift.

Keep movement subtle.

28.5 Number Animation

Impact statistics may animate from:

0 → final number

The animation should complete quickly and should not prevent the user
from reading the value.

29. Page Transitions

Page transitions may use subtle fades or directional movement.

Not delay navigation.

30. Animation Technology

Primary animation technology:

Framer Motion

Potential future use:

31. Reduced Motion

The website must respect:

prefers-reduced-motion

Users who request reduced motion should receive a simplified experience.

Animations must never prevent access to information or interaction.

32. Performance and Motion

Animations must not significantly reduce performance.

Avoid:

Heavy continuous animations.
Large WebGL scenes.
Excessive blur effects.
Continuous expensive JavaScript calculations.
Unnecessary animation loops.

Prefer transform and opacity based animation where possible.

33. Responsive Animation

Animations should adapt to device type.

Desktop may support:

Hover effects.
Parallax.
Larger motion compositions.

Mobile should simplify:

Hover-dependent interactions.
Heavy parallax.
Large decorative animations.

The mobile experience takes priority over decorative effects.

34. Loading States

Loading states must be designed rather than showing a blank screen.

Appropriate approaches include:

Skeletons.
Lightweight placeholders.
Simple fade-ins.

Avoid excessive animated loaders.

35. Empty States

If no activities, events, news, or gallery items exist, show a useful
message.

Do not leave large blank sections.

36. Error States

Add unnecessary effects.
Place it on backgrounds where it becomes unreadable.

Provide appropriate clear space around the logo.

43. Dark Mode

Dark mode is not required for V1 unless it clearly supports the
approved visual identity.

Do not add dark mode simply because modern websites often include it.

A single strong visual theme is preferable to two poorly designed themes.

44. Responsive Breakpoints

Use responsive breakpoints appropriate to the application rather than
designing only around specific devices.

The exact breakpoint values should be determined through the frontend
implementation while preserving the intended visual hierarchy.

45. Browser Support

The website should work correctly on modern versions of:

Chrome
Edge
Firefox
Safari
Mobile browsers

Do not optimize for obsolete browsers unless the organization has a
specific requirement.

46. Component Design Philosophy

React components should be reusable where reuse provides actual value.

Examples:

Navbar
Footer
Button
SectionHeading
ActivityCard
EventCard
NewsCard
TeamMemberCard
FormField

Do not create components for every tiny piece of markup.

Avoid unnecessary component abstraction.

47. Design Tokens

Common values should be represented through reusable design tokens.

Examples:

Colors
Font sizes
Font weights
Spacing
Border widths
Radius
Motion duration
Easing
Container widths

This makes visual changes easier to maintain.

48. Motion Tokens

The project should use consistent motion values rather than random
durations.

Conceptual tokens:

--motion-fast
--motion-normal
--motion-slow

--ease-standard
--ease-emphasis

The exact values may be adjusted during implementation.

49. AI Frontend Implementation Rules

Copilot and Codex must read this document before implementing any
frontend feature.

They must:

Follow the visual direction defined here.
Avoid generic AI-generated website patterns.
Avoid inventing a separate visual style for each page.
Reuse established design tokens.
Reuse approved components.
Keep animations purposeful.
Respect reduced-motion preferences.
Prioritize mobile responsiveness.
Avoid unnecessary dependencies.
Avoid unnecessary decorative elements.
Avoid excessive cards.
Avoid excessive rounded containers.
Avoid excessive gradients.
Do not copy another company's design.
Do not implement visual features only because they are trendy.
Keep performance in mind.
## Brand Color Rule

AI coding agents must not invent or randomly select brand colors.

Before implementing the frontend color system, use the official
Alliance Yuwa Club logo as the visual reference.

If the exact brand colors cannot be confidently determined, the AI agent
must report that limitation rather than inventing values.

Any proposed color palette must remain consistent with the official club
identity.
50. AI Visual Decision Rule

Before implementing a major visual section, the AI agent should be able
to answer:

What is this section communicating?

Why is it composed this way?

How does it support the Alliance Yuwa Club identity?

Why is this animation necessary?

Could the same information be communicated more clearly with less
visual complexity?

If these questions cannot be answered, simplify the design.

51. UI Change Tracking

Significant visual changes must be documented in:

docs/AI_CHANGELOG.md

The entry should explain:

What was changed.
Why it was changed.
Which design principle it follows.
Which components were changed.
Which animations were added.
Whether a dependency was added.
Whether the change affects responsive behavior.
52. Design Review Process

Before a major page is considered complete:

Desktop review
        ↓
Tablet review
        ↓
Mobile review
        ↓
Accessibility review
        ↓
Performance review
        ↓
Motion review
        ↓
Content review

The website should still look strong when animations are disabled.

53. Progressive Enhancement

The website must remain usable if:

JavaScript fails.
Animations are disabled.
Images load slowly.
The user has reduced-motion enabled.

Motion and visual effects enhance the experience but must not be
required for basic functionality.

54. V1 Visual Priority

When time is limited, prioritize:

1. Typography
2. Layout
3. Real content
4. Photography
5. Color
6. Micro-interactions
7. Complex animations

A well-designed static section is better than a poorly designed section
with impressive animation.

[ ] Feels distinctive

[ ] Strong typography
[ ] Strong visual hierarchy
[ ] Clean composition

[ ] Good mobile experience
[ ] Purposeful motion
[ ] Fast and responsive
[ ] Accessible
[ ] Consistent across pages
